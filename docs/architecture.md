# 自主规划短剧 Agent —— 架构方案 v3（ComfyUI 作为执行内核与共编画布）

> v2 我把 ComfyUI 判成"参考物"，是错的。错在**用"推理引擎"的标准去评估它**——它真正值钱的是图执行语义、节点契约、可视化共编，这三样恰好是"AI 生成工作流"最缺的底座。
> 本版按你的方向重写：ComfyUI 全量保留，LLM 是工作流作者，人是审阅者与共编者。

## 现状（2026-10-28）

产品已经收敛为一个自包含目录 `app/`，不再依赖仓库外的 `ComfyUI-master`、`runtime/`、`deepseek-harness`：

```
app/
├── src/                        前端（React + TS）
├── src-tauri/                  桌面壳（Tauri + Rust）
├── engine/
│   ├── ComfyUI/                执行内核（0.43，原样保留）
│   ├── venv/                   CPU torch，独立 Python 3.13
│   └── workspace/              ComfyUI base-directory
│       ├── custom_nodes/storyforge_ark/   自写节点 + prompts 资产
│       ├── input/ output/ temp/ user/     运行时数据
│       └── models/                        空目录（只走 API 节点）
├── docs/                       本方案 + 接口参考 + 历史归档
└── scripts/                    节点库生成
```

已经跑通（M0–M2.5 / M3 开放画布与智能体编辑权 / M4 用量 / 自我完善第一环）：

- 对话 → **短剧计划** → **确认卡片改参** → 确认门 → 编译器生成 ComfyUI 图 → 校验 → 执行 → 分镜板回显
- **开放画布（M3 完成）**：工作流页是自研 SVG 节点画布——分层自动布局、拖动节点、拖端口改连线（类型实时校验）、未连接输入标红、点节点改参数；**想放什么都可以**：节点选择器从 394 个可执行节点搜索添加（自动补默认值）、任意节点可删除（自动清理指向连线）；「重跑这版」经 `executeEditedGraph` 校验后执行并回注对话。已运行时实测：加节点、删节点、参数修改、连线改接都真实过 ComfyUI 执行出图
- **智能体同等编辑权（ops 协议，一切皆操作）**：人和智能体共用同一个图操作引擎 `graphOps.ts`（add/remove/connect/disconnect/set/setMeta，类型校验只有一份）。人对画布拖拽最终也走这套操作；智能体在对话里输出 ops 序列（提示词带 394 节点目录 + 当前图 JSON），应用后进 `pendingGraph` 在画布上标 • 等人审查，重跑才执行——智能体有完全编辑权但没有执行权。已运行时实测：对话"把 #3 的 images 直接连到 #1"→ 模型输出 disconnect+connect → 画布呈现 → 重跑出图
- **自我完善（对话驱动进化）**：执行失败时 `executePlanWithRepair` 自动把错误喂回模型修订计划（最多 1 次），模型同时输出一句 `lesson` 沉淀进 `memory.learnings`（上限 30 条，设置页可查看/清空）；之后每次出计划和修复都会注入这些经验。修复提示词构建/解析为纯函数，已离线断言
- **确认门 + 预算上限**：`budget.maxShots` / `budget.maxSeconds` 超限自动截断（默认 3 镜 / 30 秒）
- **确认卡片参数编辑**：景别、运镜、时长（4-15s）、台词、动作都能在确认前直接改
- **单镜重跑**：`executePlan` 接受单镜子计划，分镜板每张卡可直接重跑那一镜
- **尾帧接续**：多镜时编译器把上一镜 `DramaContinuity` 的尾帧接给下一镜 `DramaShotFrame.previous_frame`，画面衔接连续
- **成片拼接（M5 完成）**：`engine/assemble.py`（PyAV 解码→重编码，libx264 crf18 + aac）+ Rust 命令 `assemble_shots`；分镜板「合成成片」按钮把一次计划的所有镜头视频拼成一个 mp4，产物落到 `output/storyforge/film/` 并作为资产挂回该次执行（分镜板/资产页直接播放）。已实测：两段 4.04s 真实镜头 → 8.13s 成片，2.1s 完成。已修的坑：PyAV 19 的 `start_encoding` 显式头、`add_stream_from_template` API、B 帧负 dts 归零、共享 demux 位置导致音频包丢失
- **用量统计**：LLM usage（Rust 侧透出 `usage`）+ ComfyUI 产物 metadata（kind/duration）汇总成 `RunUsage { llmTokens, images, videoSeconds }`；分镜/资产页展示单次与累计用量（只记量，不换算金额——各模型价格常变）
- 计划模式不把全量节点塞给模型：LLM 只写语义计划，图由 `plan.ts` 编译，避免幻觉节点
- 领域节点：`DramaCharacter`（定妆）、`DramaShotFrame`（分镜首帧）、`DramaShotVideo`（镜头视频）、`DramaContinuity`（尾帧接续）；节点库 1027 个，394 个可直接执行，305 个需本地权重（校验器拦截）
- 桌面端托管 ComfyUI，`--base-directory` 指向 `engine/workspace`；对话 Key 与 ARK Key 分离，ARK Key 自动注入节点进程
- Seedance 2.5 首帧被真人审核拦截时，视频节点自动改用角色定妆图的原始 URL 走参考图模式

尚未开始：字幕烧录与音轨替换、成本换算金额、记忆的手动编辑、计划角色锚点编辑、智能体主动提议画布改动。

## 0. 先修正一个判断

| 我 v2 的误判 | 事实 |
|---|---|
| "本机无 GPU，ComfyUI 跑不了" | ComfyUI 只做**编排与调度**，推理走 API 节点。CPU 就能跑，models 目录空也不影响 |
| "火山接口封装好了，节点用不上" | 火山接口只给你"一次请求"；节点给的是**可组合、可校验、可复用、可被人改**的生产单元。这两件事不在一个层次 |
| "ComfyUI 的死板来自节点" | 死板来自"**必须人来画图**"。节点本身是资产，不是负担 |

正确的关系是：

> **ComfyUI 提供"工作流这门语言的语法和运行时"，LLM 负责"用这门语言写作"，人负责"审稿和改稿"。**

缺任何一环都不成立：
- 只有 ComfyUI → 就是现在的样子，人画图，门槛高。
- 只有 LLM + 裸 API → 每次即兴拼请求，不可复现、不可编辑、不可复用，人插不上手。
- **两者 + 人 → 才是你要的东西。**

## 2. 四个真正的工程难点

这四件事决定项目成不成，比"接哪个模型"重要得多。

### 难点一：节点库塞不进上下文

ComfyUI 全量节点（核心 + 内置 API 节点 + custom nodes）上千个，`/object_info` 序列化后几十万 token。直接把节点表丢给模型，必然超限且噪声极大。

做法：
1. 启动时拉全量 `/object_info`，归一化成"节点卡"（id / display_name / category / description / inputs 的 name+type+required+default+options / outputs）。
2. 建索引：按 category 分桶 + 文本 embedding。
3. 检索：对话意图 → 召回 top-k（k≈15–25），**按 category 保证覆盖**（不能全是图像节点、漏掉视频节点）。
4. 同时检索"子图模板"——一个模板顶 8 个节点，对模型更友好。
5. 上下文预算控制在 4–6k token。

> 这一步做不好，后面全是幻觉节点。

### 难点二：AI 生成的图一定是错的

模型会写不存在的节点、漏必填项、把 IMAGE 接到 STRING、搞出环。必须有硬校验：

| 层 | 检查 | 失败处理 |
|---|---|---|
| 结构 | class_type 存在、必填输入齐全、连线类型匹配、无环 | 报错回模型，带具体节点 id 和字段 |
| 语义 | combo 值在 options 内、时长/尺寸在范围、模型名有效 | 同上 |
| 执行 | ComfyUI `/prompt` 返回 `node_errors` | 原样回喂，最多重试 2 轮 |
| 兜底 | 两轮仍失败 | 降级到最接近的模板，标注"已降级，请人工确认" |

**不允许静默失败，也不允许无限重试。** 这是"AI 不可靠"的工程兜底。

### 难点三：提示词必须是资产，不能即兴

你说"提示词很重要"，我完全同意——但重点不是"写得漂亮"，是**逐字稳定**。

```
最终 prompt = 风格前缀（style-bible）
            + 角色锚点（characters.yaml，逐字复用，永不改写）
            + 镜头语法（景别/运镜/光线，来自受控词表）
            + 动作与台词
            + 负向约束（negative）
```

四个文件，全部版本化：
- `prompts/style-bible.yaml` — 全片风格前缀（冷调赛博 / 暖调胶片…）
- `prompts/characters.yaml` — 角色锚点（外貌、服装、气质），**逐字复用**
- `prompts/shot-grammar.yaml` — 景别、运镜、光线的标准词表（避免"推镜/推进/慢慢靠近"三种说法）
- `prompts/negative.yaml` — 负向词库（手部、文字、畸变）

节点内部封装这套拼装逻辑：人/模型只填语义参数（角色、景别、情绪），节点负责生成最终 prompt；同时留 `prompt_override` 口子给高级用户。

### 难点四：人机共编的双向同步

这是"不能全靠 AI"的落地关键，也是最容易被忽略的地方。

| 方向 | 机制 |
|---|---|
| 对话 → 画布 | agent 生成的 graph 通过前端 API 载入画布（`loadGraphData`），人立刻看到并可编辑 |
| 画布 → 对话 | 监听 workflow 保存/变更，算出 diff，作为上下文注入给 agent："人把第 3 个节点的 duration 从 5 改成 8" |
| 冲突 | **人优先**。画布是最终事实，agent 后续操作基于最新画布状态 |

没有这条双向通道，"人机协作"就只是一句口号。

## 3. 火山接入：两条路，我推荐第二条

ComfyUI 内置了 `nodes_bytedance.py`（18 个节点，301 处火山相关引用），但——

```
BYTEPLUS_IMAGE_ENDPOINT = "/proxy/byteplus/api/v3/images/generations"
```

它走的是 **Comfy 官方代理**（`/proxy/...`），需要 Comfy 账号与额度，**用不了你自己的火山 ARK Key**。

| | 路 A：内置 bytedance 节点 | 路 B：自写节点直连火山（推荐） |
|---|---|---|
| 凭证 | Comfy 账号 + credits | 你自己的 `ARK_API_KEY` |
| 成本 | 走 Comfy 计价 | 走火山计价，可控 |
| 可控性 | 参数被封装，改不了 | 全参数可控，可加短剧语义 |
| 开发量 | 0 | 1–2 天（有 `comfy_api` 的 `IO.Schema` 规范，不复杂） |
| 扩展 | 不能加自定义逻辑 | 可以加"角色定妆""尾帧接续"等领域节点 |

路 B 的节点照抄内置节点的参数设计即可（`ByteDanceFirstLastFrameNode` 的 model/prompt/first_frame/last_frame/resolution/aspect_ratio/duration 就是标准答案），但把 endpoint 指向 `https://ark.cn-beijing.volces.com/api/v3`，用你的 Key。

## 4. 短剧领域节点（回应"节点设计很重要"）

通用节点的问题是：拍一个镜头要连 8 个节点，模型容易错，人看着也累。
领域节点把"语义"收进一个节点，但**不是黑盒**——点开是可展开的子图，能看到里面真实的节点连线，能改。

| 节点 | 语义参数 | 内部 |
|---|---|---|
| `DramaCharacter` 定妆 | 角色描述、风格、候选数 | 多图参考 + 固定 seed + 组图生成 → 输出角色参考图 |
| `DramaShotFrame` 分镜首帧 | 角色(IMAGE)、景别、运镜、动作、情绪 | 拼 prompt + 注入角色参考 → 输出 IMAGE |
| `DramaShotVideo` 镜头视频 | 首帧、可选尾帧、时长、运镜、台词 | 火山 Seedance → 输出 VIDEO |
| `DramaContinuity` 接续 | 上一镜 VIDEO | 取 last_frame → 作为下一镜首帧 |
| `DramaAssemble` 合成 | 镜头列表、字幕、BGM | ffmpeg 拼接 + 字幕烧录 → 成片 |

设计原则：
1. **参数是语义的**（"中近景""缓慢推进"），不是裸 prompt。
2. **内部可展开**，人随时能拆开改。
3. **输出类型守规矩**（IMAGE/VIDEO），能接回通用节点。
4. 先做 5 个，够拍完一支样片；不够再加。

## 5. 人机协作的三个层次

不是"AI 全自动 + 人点确认"，而是三档可切换：

| 档位 | 谁主导 | 适用 |
|---|---|---|
| **共驾**（默认） | AI 出图，人改图；AI 出计划，人改计划 | 日常生产 |
| **AI 主导** | 一次生成整段，人只在粗剪时看 | 批量试错、找灵感 |
| **人主导** | 人在画布上搭，AI 只做补全和填参 | 精细镜头、特殊效果 |

界面上就是一个开关，不是一个哲学问题。

## 6. 里程碑

| 阶段 | 内容 | 验收 | 预估 |
|---|---|---|---|
| **M0 环境** | ComfyUI 独立 venv（CPU torch）+ 前端可访问；custom node 骨架；火山 Key 打通一张图 | 浏览器打开画布，跑通一个自写火山节点 | 1 天（含依赖下载） |
| **M1 作者闭环** | 节点库索引 + graph 生成 + 校验自修复 | 说"生成一张竖屏雨夜人像"→ 模型自己出图并跑通 | 2 天 |
| **M2 领域节点** | `DramaCharacter` / `DramaShotFrame` / `DramaShotVideo` + 计划 IR | 说"拍 3 个镜头"→ 出分镜图 + 视频 | 2 天 |
| **M3 共编回路** | graph 载入画布 + 画布变更回注对话 | 人在画布改一个参数，agent 知道并据此继续 | 2 天 |
| **M4 工作台** | 分镜板 / 时间线 / 预览 / 成本条 | 界面上点选、重做、看进度 | 2–3 天 |
| **M5 成片** | `DramaAssemble` + 字幕 + 音轨 | 30 秒竖屏样片 mp4 | 1 天 |

**M0→M2 是生死线（约 5 天）**：如果"说一句话 → 模型自己搭出能跑的图 → 出片"这条链路成立，剩下都是工程堆量。

## 7. 风险

| 风险 | 对策 |
|---|---|
| 模型生成幻觉节点 | 检索 + 硬校验 + node_errors 回喂 + 降级模板，四道闸 |
| 上下文爆掉 | 节点卡精简 + top-k + 子图优先 |
| 角色不一致 | 定妆锁定 + 多图参考 + 锚点逐字复用 + 固定 seed |
| ComfyUI 升级破坏 custom node | 锁 0.43.0，节点用官方 `IO.Schema` 规范写 |
| CPU 装 torch 慢/大 | 只装 CPU 版；D 盘 111G 够 |
| 双向同步丢改动 | 画布为事实源，变更即快照，冲突人优先 |
| 成本失控 | 内容寻址缓存 + 预算门限 + 单镜重跑而非整片重跑 |

## 8. 已确认的两点

1. **火山 Key 通道**：LLM 走普通按量 `/api/v3`，Agent Plan 时在设置里改成 `/api/plan/v3`；两者不混用。
2. **采用路 B**：自写节点直连火山，用你自己的 ARK Key；内置 bytedance 节点只作为参数设计参考。

M0–M2.5、M3（开放画布 + 智能体 ops 编辑权）、M4（用量统计）与自我完善第一环已完成；下一步：M5 成片拼接，或让智能体主动提议画布改动。
