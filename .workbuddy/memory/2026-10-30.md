# 2026-10-30

## StoryForge：流式对话 + 画布复刻 ComfyUI + 干掉演示模式

背景：用户三条反馈——①界面不够丝滑；②画布连线有时看不见、连线不吸附、要 ComfyUI 那套（双击加节点、右键菜单）；③「怎么还是演示模式，要能真实使用」。

### 真机自测（关键，别只靠类型检查）

用 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS="--remote-debugging-port=9222" pnpm tauri dev` 起真机，再用 Node 内置 WebSocket 连 CDP（`/json` 拿 webSocketDebuggerUrl → `Runtime.evaluate`）直接驱动 `window.__sfStore`，这是本项目最有效的自测手法：能读真实 state、能发消息、能 `Page.captureScreenshot` 截图看真实界面。临时脚本放 `.workbuddy/tmp`，用完删。

首次自测就抓到两个「用户说还是演示模式」的真因：

1. **跑的是旧二进制**。Rust 新增了 `llm_chat_stream`，不重启 `tauri dev` 就没有这个命令，`invoke` 直接 reject。
2. **持久化里的旧 `degraded` 标记**。`storyforge.sessions.v2` 里躺着 1 条 `meta.degraded=true` 的历史消息（是旧代码无条件降级时写进去的），每次启动都恢复出来，界面上就一直挂着「演示模式」标签。现在 `loadPersisted` 读入时清掉这个字段，tag 文案也从「演示模式」改成「本地占位图」，只在真没配 key 时出现。

### 第二个真问题：推理模型偶发「只想不说话」

真机跑第一轮就复现：`400/400` 分片全是 `reasoning_content`，`content` 一个字没有，`finish_reason` 未知。所以 `parseJsonLoose("")` → null → 报「模型没给出可解析的 JSON」。这不是代码 bug，是 deepseek-flash 偶发行为（同一 prompt 重试即成功，用 Python 直打也能成功）。

对策（都在 `llmJsonChat`）：
- Rust 侧把 `finish_reason` 一起返回（`finishReason`），便于判断是不是 `length` 烧完了
- `content` 为空但 `reasoning` 非空 → **自动再要一次**，并且这次去掉 `response_format`（换一条采样路径比改动提示词更有效），附加一句「只输出 JSON 正文，不要思考」
- 步骤 note 里带 `finish_reason`，detail 在正文为空时展示思考，便于事后定位

### 演示模式的真实原因（不是配置问题）

实测配置本身是好的：`com.deepseek... / com.storyforge.desktop/config.json` 里 `llm.model=deepseek-flash`、key 35 字符可用，`ark` key 46 字符在。用真 key 直打 `/chat/completions` 能返回合法 JSON。

问题在代码：`runAgentTurn` 的 `catch` 无论什么原因失败都 `degraded = true`，然后落到 `demoGraph()` 占位图分支——所以任何一次网络抖动/JSON 解析失败都会显示"演示模式"。修法与要点：

- 只要配了 `llm.apiKey`，失败就**直接报错并说人话**（`humanError()` 把 NO_KEY / HTTP 401/402/404/429 / 超时 / 连接失败翻成中文），不再退回占位图
- `demoGraph()` 现在只有「压根没配 key」才可达
- 模型返回非 JSON 时，把原始输出片段摊给用户，而不是假装成功
- 设置页加「测试连接」（`llmPing`）：先落盘再打一次最小请求，返回「耗时 · tokens · 回复」

### 流式输出（对齐 DSH 的呈现）

- Rust 新增 `llm_chat_stream`：`stream:true` + `stream_options.include_usage`，自己按行切 SSE（`reqwest::Response::chunk()`，不加依赖），逐块 `emit("llm://delta", {streamId, kind, text})`，`kind ∈ reasoning|content`
- 前端 `api.llmChatStream` 订阅 `llm://delta` 并按 streamId 过滤，`finally` 里必 unlisten
- `agent.llmJsonChat` 改成走流：失败时去 `response_format` 重试一次
- `extractPartialReply()` 从正在到达的 JSON 里按转义规则抠出 `"reply"` 的当前值 → 正文边生成边显示（实测 reply 字段在第 3 个 chunk 就出现）
- `ChatStep` 模型（think/tool/output + status + note + detail），`store` 里 `beginTurn → makeHandlers → endTurn` 统一所有产出助手消息的动作（send / confirmPlan / runAndAnnounce / rerunGraph / rerunShot）
- `ChatPanel` 渲染：`已思考 N 字` 折叠块（点开看 reasoning 原文）、工具步一行一条（spinner / ✓ / ✗ + 右对齐结果 + 点开看原始输出）、正文尾部 `.caret` 方块光标

### 画布：连线看不见的真正原因

不是样式问题，是**行索引错位**：`portPos()` 用 `Object.keys(node.inputs)` 的序号定位输入行，而渲染用的是 `inputRows()`（card spec 顺序 + 补漏）。两者顺序/数量不一致时，连线锚点算错，线就画到节点外面或看不见。输出锚点同理，还漏了输入区后面的 4px 分隔留白。

改法：`inAnchor(p, i)` / `outAnchor(graph, id, p, j)` 与 DOM 布局严格对齐（端口 14px、外扩 8px、`OUT_GAP=4`），`nodeHeight()` 同源计算；SVG 用 `overflow: visible` + 大尺寸画布，负坐标也不裁。

### 画布交互（照 ComfyUI 复刻）

- 滚轮在指针处缩放（`exp(-deltaY*0.0016)`，0.3–2.4），用函数式 `setView` 保证连滚不丢增量；`Shift+滚轮` 横移
- 空白拖动平移（左键/中键/空格抓手），`Ctrl+拖` 框选；单击空白清选择
- 双击空白 → 光标处弹节点搜索（回车加第一个）；右键三套菜单：画布（加节点/全选/适应/重排）、节点（复制/断开全部连线/删除）、连线（删除）
- 拖连线时扫描所有兼容端口，30px（按缩放折算）内吸附 + 白圈高亮 + 端点亮环；类型不兼容的端口降透明度
- 连线按 ComfyUI litegraph 槽位配色上色，14px 透明命中区可点选，`Del` 删除；`Ctrl+A` 全选、`Del` 删节点、`Ctrl+D` 复制
- 右下角缩放控件（−/%/+/适应），首次进图自动 fit（缩放下限 0.62，再小就没法读了），`fitPending` ref 只在真的算出结果后才清
- 节点拖动吸附 8px 网格；从已连线的输入拖走时只有真的移动了才断开（纯点击不毁线）

### 坑

- `preview.tsx` 打桩时 `positions` 首帧为空，连线计算会 `undefined.x` 崩——所有 `positions[..]` 访问都要判空
- Tailwind 任意值里 `calc(100vh-300px)` 缺空格是非法 CSS，整条 `clamp()` 被丢弃；改用内联 `style`
- 无头 Chrome 依然必须给 `--screenshot` 传 Windows 绝对路径；`| head` 会把 vite 后台进程一起带走，要直接 run_in_background

### 验证

`tsc --noEmit` + `vite build` 通过；用打桩 preview 截图核对了画布（连线贴端口、自动 fit、类型色）、对话（思考折叠 / 工具步 / 流式光标）、设置（测试连接按钮）。临时 preview 文件已删。

## 23:5x 架构转向：对话只管说话，动手全在画布

用户打断并要求：对话区只做对话相关功能，AI 在画布上做具体编辑，不许在对话里让用户调参数；一切与"生成什么"相关的都必须在画布区实现，AI 要能完全控制画布。

### 落地改动
- store：`pendingPlan/pendingGraph/scratch/confirmPlan/discardPlan/updatePendingShot/clearPendingGraph/setScratchGraph` 全部删除，换成单一 `draft: CanvasDoc`（id/graph/plan/title/status/note/fromAI/ts）+ `setDraftGraph / runDraft / resetDraft`。`send()` 里把 plan 编译成图或 ops 结果直接发布到 draft，并把 tab 切到画布。
- ChatPanel：删掉 `PlanCard`（约 150 行），对话区只剩消息流 + 输入框。
- CanvasGraph：props 改成 `doc / busy / baseGraph / onGraphChange / onRun / onReset`；去掉"编辑/只读"切换（永远可编辑）；工具栏变成「状态标签 + 节点数 + AI 刚改过 + 删除 + 还原 + 开始生成」；参数编辑器从画布下方移到画布内右上角浮动检查器（300px、可滚动、带收起按钮）。
- Workspace：默认 tab 改成 `graph`，标签「工作流」→「画布」并排第一。
- agent.ts：确认门文案改成"图已经搭到画布上了…点画布上的「开始生成」"；ops 路径文案改成"改动已放到画布上"；提示词加"画布是你的工作台，不是用户的工作台，绝不要求用户自己去调参数"；执行后 reply 改成"画布已执行（N 个节点），产物在「分镜」里"。
- runDraft：执行记录补 `plan`（分镜页要按计划渲染）和 `usage`（从产物反推 images/videoSeconds），`draft.id` 保持原样避免执行完画布重排。

### 踩到的真问题（都已修）
1. **draw 顺序 bug**：CanvasGraph 里同时存在本地 `graph` state 和 `doc.graph`，换图时本地 state 滞后一帧，导致自动 adapt 用了上一张图的 positions（fit 被提前消费）。修法：删掉本地 state，画布直接读 `doc.graph`（mutate → onGraphChange → store 是同步的，不需要本地副本）。
2. 自动适应视图不生效的根因就是上面这条；改完后 10 节点图能正确 fit（62%）。
3. `setDraftGraph` 里 `status: done → draft` 的翻转，正好让「还原」的可用性可以用 `!baseGraph` 判断。

- 改参数轮：`width/height` 从 512×768 改成 360 再还原，store 与画布同步、还原后回到 512/done。

## 00:5x 第二轮：让 AI 的活儿看得见、跑得动

用户原话：「AI操作的时候，人看起来也不直观，每次AI生成要有工作量，不要随便生成两个糊弄人，甚至还是不能运行的工作流」。
背景：用户自己上手试，AI 搭了一条 4 节点的视频链，但 11 号节点的首帧没接上，等于交了个跑不起来的图。

### 新增：`src/lib/graphAudit.ts`
- `diffGraph(before, after)` → added/removed/changed(keys)/linksAdded/linksRemoved/total；`diffSummary` 出一句话；`touchedIds` 给画布高亮用。
- `auditGraph(graph)` → error/warn 两级：未知或需权重的节点、必填输入没接、引用已删除节点、标量输入接了线、没有保存终点、从终点走不到的孤岛。
- `hasGenerator(graph)`：图里有没有真的调模型的节点（Drama* 或带 model 输入），防"只有占位画面"的糊弄图。

### 交付闸门
- agent.ts ops 路径：applyGraphOps → validateAndRepair → auditGraph。**只算本次新引入的问题**（先对 lastGraph 建 baseline 集合），有问题就自己再问模型一轮（最多 2 轮，"自查修复 N" 会作为工具步骤露出来）；还不干净就 `graph: opts.lastGraph` 整版撤回、`graphEdited:false`，画布不动。
- `applied.length === 0` 时也不许说"改好了"，明确说没落到图上。
- 旧的 `parsed.graph` 路径不再直接执行：改成审计后只放画布（`graphEdited:true`），无生成节点时直接拒绝。
- store.send()：计划编译出的图先 `validateAndRepair` + `auditGraph`，有 error 就不发布（`publishError`），画布保持原样。
- store.runDraft()：执行前跑同一套审计，有 blocking 就拦下 + `focus` 指到出问题的节点 + 落一条说明消息。
- 输出质量：模型返回非 JSON 时先判断"像不像人话"（`looksLikeProse`：CJK≥4、≠碎 JSON/代码），不像就重要一次（"重来一次"步骤）；再不行如实说两次都失败。之前碎片文案会被当成闲聊直接展示给人。

### 看得见
- CanvasDoc 增加 `change: GraphDiff` / `changedAt`；画布上 AI 碰过的节点亮 7 秒（`.ai-touch` 呼吸动画 + 标题旁「AI 改」小标）。
- 左下角「AI 改了什么」卡片：`+N 节点 · 改 N 处 · 连线 ±N`，逐条列出（新增绿＋、修改橙色·、删除划线－），点一条 `focusNode(id)` → 画布居中 + 选中 + 打开右上角参数检查器。
- 人一动手（setDraftGraph）就把 change/changedAt 清掉，避免旧单子误导。

### 能停
- `cancelRequested` + `cancelRun()`：按钮忙时变「停止」，断开引擎、`ensureComfy/startComfy` 的等待循环逐秒检查标志并及时返回；等待时 stage 会写"引擎启动中 · 已等 Ns"，不再停在"校验画布"一动不动。
- `stopComfy` 复位 `starting`，避免别处白等 90 秒。

### 实测
- 「把视频节点时长改成 8 秒」→ 1 处改动、change 记录正确、高亮 + 卡片正常。
- 手动塞一个缺 prompt 的节点 → 点开始生成被拦：error 文案、focus=99、status=error、聊天里解释，节点被居中选中、参数面板自动打开。
- 「把图像生成节点接进视频节点」→ 模型第一次输出不可用，自动"重来一次"后成功，并把之前缺提示词的空节点顺手删掉。
- 已知：模型可能选错字段语义（例如用 first_frame_url 填文件名而不是接 first_frame 连线），静态审计查不出来，只能靠人在改动清单里看。

## 第三轮：可读性 + 别糊弄 + 引擎别一直烧（2026-10-30）

### 可选输入折叠（让多镜图整屏可读）
- 判定口径改成「没接线 + 没填值」才折叠（`hasValue`：空串/undefined/null 算没填）。只看「有没有接线」会把填了值的参数也藏起来，反而更不直观。
- `optionalKeys()` 与展开状态无关，负责渲染「＋N 可选 / − 收起可选」那一行；`foldedRows()` 才带展开状态，只给高度和锚点算数用。
- 关键 bug：`inputRows()` 末尾那段「补上卡上没声明的 key」的兜底循环会把折叠掉的键全部加回来（因为它们在 `inputs` 里有值），导致折叠看起来生效、实际节点没变矮。修法：兜底只加 `card.in` 里没声明的键。
- 实测：视频节点 410px → 334px（14 行 → 9 行 + 折叠行），展开/收起双向验证过，节点高度、端口锚点、连线位置一致。

### 引擎空闲自动停
- store 新增 `idleStopMin`（默认 5，localStorage 键 `sf.idleStopMin`）、`idleStopAt`、`armIdleStop/disarmIdleStop/setIdleStopMin`；模块级 timer，切页面不会重复挂。
- 三个收尾点挂计时：`runDraft`、`runAndAnnounce`、`assembleShots`；开跑前先 `disarm`；正在跑时到点会顺延，不打断。
- 设置页 ComfyUI 段加了「空闲自动停」选择（不自动停/2/5/10/30 分钟）；状态栏在运行时显示「· 空闲 5 分自动停」。
- 用 3 秒阈值实测过：arm → 到点 → 日志「ComfyUI 空闲 0.05 分钟，已自动停」→ `idleStopAt` 归零。

### 「整版重铺」要说实话
- 真机跑「拍一个新镜头」发现：计划路径重新编译分镜时节点 id 会撞上旧图（`shot_1_*`），`diffGraph` 只能差出「改 3 处」，看着像没干活，实际整张图被换掉。
- `CanvasDoc` 加 `rebuild: {before, after, replaced}`：新图 id 全落在旧图 id 里时判定为重铺；对话回复追加一句「原来那 N 个节点整版换掉了」，清单标题变「AI 重铺了整张图 · 旧 5 → 新 5 节点」，条目不再列"改了哪几个参数"。
- 工具栏「AI 刚改过」改成可点开清单的按钮，并带 `· 改 N 处 / 整版 N 节点` 摘要。
- ops 路径和人工改图都要显式清 `rebuild`，否则上一轮的标记会被误读成这一轮也重铺了。

### 未做
- 逐镜实时进度（要接 ComfyUI `/ws` 的 executing/progress）。
- 折叠状态不随图持久化。
- 计划路径仍是"整块 storyboard 覆盖"，不做增量追加（要做需要给 compilePlan 加 id base，并解决多镜编号与尾帧接续的冲突）。

### 顺手修的两个小毛病
- 自动适应在首帧量不到容器大小时会算出 100%，节点顶到画布外：`fitView()` 现在 w/h 小于 120 直接返回 false（不算，等下次），并加了一个 ResizeObserver 在容器真有尺寸后补一次。
- 重启后画布还挂着上一场的「AI 刚改过 / 整版重铺」和残留的 `running` 状态：`init()` 恢复草稿时清掉 `change/rebuild/changedAt/fromAI`，`running` 落回 `draft`。

## 第四轮：生成时画布不再"死着"（/ws 逐节点进度）

## 第五轮：AI 铺图动画 + 真能停掉一轮对话

### 铺图动画（看得见 AI 在干活）
- `revealOrder` 在 **render 阶段**用 `useMemo` 算（不是 effect）：第一帧就已经把还没长出来的节点藏好，否则会先整张图闪一下再开始演。
- 只演"新增"的节点（`change.added`）；改参数的节点原位高亮就行，藏一下再冒出来更像闪烁。整版重铺时演全部节点。
- 数量关卡：3 ~ 48 个才播，110ms 一个；工具栏同步数「铺节点 3/5」，左下改动清单跟着一条条长。
- 隐藏态**不能带 transition**，否则挂载那一帧会从 opacity 1 淡到 0——看着就是闪一下。做法：`notYet && "opacity-0"`，`!notYet && "transition-opacity duration-200"`。
- 连线跟着端点走：`links` 里补了 `src`（上游 id），两端有任何一个还没长出来就整条线 opacity 0。

### 停掉正在跑的一轮对话
- Rust：`LLM_STREAMS: OnceLock<Mutex<HashMap<stream_id, Arc<AtomicBool>>>>`，新增 `llm_abort(stream_id?)` 命令；`llm_chat_stream` 注册旗标、每个 chunk 检查、退出时摘掉，返回体加 `cancelled`。
- api.ts：记住 `activeStreamId`，`llmAbort()` 掐当前流。
- agent.ts：`export const CANCELLED = "__cancelled_by_user__"`，`llmJsonChat` 撞到 `resp.cancelled` 抛这个哨兵；runAgentTurn 里那个"模型调用失败"的 catch 必须**原样 rethrow**，否则会被包装成失败文案（第一版就踩了）。
- store：`stopTurn()`——生成中（`draft.status === "running"`）转给 `cancelRun()` 断引擎，否则立 `cancelRequested` 并掐流；`send` 的 catch 识别哨兵 → 回"已经停了，画布没动。"、error 置空。
- ChatPanel：busy 时发送键换成方块停止键。

### 顺带修
- `runDraft` 的两个早退分支（用户取消 / 引擎没起来）以前不复位 `draft.status`，标签会一直停在"生成中"；现在分别落回 `draft` / `error`。
- ComfyUI 冷启动 90s 不够（实测 CPU 模式这次要 100s+，还刚好在超时后起来）：等待上限全部改成 180s，超时也**不再谎报"启动失败"**，改为再查一次状态 + 说"还在启动，稍后再点开始生成"。

## 第六轮：分镜页跟着跑 + 产物不再依赖引擎

### 分镜页实时镜像
- 分镜页以前只在跑完之后才出现（`runs` 里有了才渲染），生成那几分钟这一页是空/旧的。现在 `needsLive = !!draft.plan && draft.status !== "done"`：没跑完/没跑过/上次失败，顶上摆的是"正在跑的镜像"（`LivePlan`），历史卡片退到下面，跑完自动换回正常历史卡。
- `shotState(runNodes, n)` 按节点 id 前缀 `shot_N_` 认领这一镜的全部节点：有 err → 出错；有 run → 跑着（显示它的 pct）；全 done/cache → 完成；一个都没有 → 排队中。
- 卡片状态：跑着给 spinner + 百分比 + 底部进度条 + 「生成中」标；完成打勾 + 「完成」；未开始按 status 改文案（生成中「排队中」/ 待生成「还没生成」/ 失败「没跑完」）。
- 头部的动作按钮跟 status 联动：`running` → 停止；`draft` → 开始生成；`error` → 再试一次。
- 实测（真 app + CDP）：用 `compilePlan` 现编一份 4 镜计划塞进 draft（节点是真实的 `shot_N_*`），注入与 ws 归约同形的 `runNodes`，截图确认「✓ / 42%+进度条+生成中 / ✓(缓存) / 排队中」四处对，副标题「已完成 2/4 · 正在跑第 2 镜」也对；status 打成 error 时标签变「上次失败」、按钮变「再试一次」。
- 「开始生成」按钮真的会走 `runDraft`：故意删掉 `shot_2_frame` 再点，被审计拦住——`error="画布还跑不了：…"`、`focus=shot_2_save`、`comfy.running=false`（没花钱、没起引擎）。

### 产物走本地文件协议
- 以前所有 asset 的 url 都是 `http://127.0.0.1:port/view?…`：ComfyUI 一停（空闲自动停/手动停/重启应用）历史里的图全变破图，而文件其实一直在 `output/` 里。这是自己的毛病。
- Rust 新增 `comfy_output_dir()`（`comfyBase/output` 的绝对路径）；`tauri.conf.json` 开 `assetProtocol.enable + scope ["**"]`（`protocol-asset` feature Cargo.toml 里本来就有）。
- `lib/media.ts` 的 `mediaSrc(a)`：有 outDir 就 `convertFileSrc(joinPath(dir, subfolder, filename))`，没有就退回 `/view`；内部直接读 `useStore.getState().outDir`，省得把 outDir 一路钻到 ShotCard/PlanRun/zoom 每个小组件。
- 实测：引擎未启动状态下，分镜页缩略图 `naturalWidth=512`（真解码），不再出现破图图标。注意假的"空白"可能是真产物（EmptyImage 测试图本身是纯白 512×512）。
- 顺手清历史垃圾：早期版本把"人点了停止"当失败写进消息，`__cancelled_by_user__` 就留在 localStorage 里读回来了；`loadPersisted` 里加了一层清洗，读到哨兵就改写成「已经停了，画布没动。」并把残留的 running 步骤收尾。

### 调试踩坑
- CDP 截图是 1080 宽，但 `innerWidth=1440`、`devicePixelRatio=1.25`：**click 的坐标要用 CSS 像素**，即截图坐标 ÷ 1.25。直接拿截图坐标点，点空。定位元素最稳的办法是 `getBoundingClientRect()` 取中心再点。

## 第七轮：逐镜实耗 + 四个页面的排版重做

## 第八轮：逐镜成本拆三段 + 多版并排对比

### 逐镜拆「等 / 跑 / 重」
- `RunRecord.shotMs` 换成 `shotCost: Record<镜号, { wait; busy; retries }>`：
  - `wait` 上一镜结束（首镜是提交时刻 `startedAt`）到本镜第一个节点开跑的空档；
  - `busy` 本镜节点在跑的墙钟累加；
  - `retries` 同一节点 id 在本镜内被 `executing` 第二次的次数（重跑/重试）。
- 只在 `agent.ts` 的 `submitAndWait` 里收（`seenNodes` 按镜记录见过的节点 id），所有执行路径共用。
- **不编造**：云端排队发生在 ARK 节点内部，`/ws` 看不到，所以那部分算进 `busy`，「排队」只代表本机队列——README 的能力边界里写明了这点。
- 展示：卡片「实耗 3.1s」(busy)、表头「生成 X · 排队 Y（≥0.5s 才显示）· 重跑 N 次」、页脚胶囊「镜号 + 灰(等)/亮(跑) 双色条 + 秒数 + ↻N」，`title` 里给完整拆分。

### 多版并排对比
- 分镜页顶部 `chip`「多版对比 N」进入对比视图：`CompareBoard`，`grid-template-columns: 34px repeat(n, minmax(0,232px))`，行=镜号、列=版本（最新在前，标「最新」）。

- 同一镜在不同版本里没产出就显示「未生成」，那一版根本没这一镜就显示「—」，不混为一谈。
- 实测：注入第三版验证三列并排、列头「最新一版 / 往前第 2 版 / 往前第 3 版」、镜号行对齐都正常。

### 收尾

## 十三、真实单镜重跑 + 画布同步 + 灯箱修复 + 项目化

**真跑验证（用户批准，1 次付费视频）**：rerunShot 全路径真跑成功——定妆→首帧→Seedance 4s 视频，产物 shot01_frame/video_00004，逐镜成本 wait 31s / busy 226s；缓存命中的 rerun3 免费复验了合并。shot-merge 纯函数全部经真实数据单测。

**画布同步修复（用户发现"画布看不到完整工作流/生成完变占位"）**：

- 教训：rerunShot 在 store.ts，CanvasGraph 数据源是 draft.graph；调试时 reload 后要等 2s+（异步 init）。
